# `/배포` — dev→main 검증 + PR + npm publish

npm 라이브러리 배포 절차. STEP 순차 실행.

## 주의

- `git push --force` / `git reset --hard` 금지.
- uncommitted 변경 있으면 중단(먼저 `/push`).
- 테스트 실패 시 배포 금지.
- `.dev.vars`·시크릿 출력 노출 금지.
- 🔒 `main` 은 branch protection 으로 **직접 push 차단**(PR 필수). 배포 승인 = `v*` 태그 push 시점(PM 결정).
- publish 는 GitHub Actions(OIDC Trusted Publisher)가 자동 수행 — 로컬 토큰·`npm publish` 불필요.
- ⚙️ **최초 1회 설정**: npmjs.com → 패키지 `kr-history-bm25` → Trusted Publisher 로 이 repo(`shyang1012/kr-history-bm25`)·workflow(`publish.yml`) 등록. 미설정 시 태그 push 후 Actions 가 인증 실패한다.

## STEP 0 — 사전 확인

```bash
git status --short          # 비어있어야 함. 아니면 중단 → /push 먼저
git branch --show-current   # dev 여야 정상
```
- 미커밋 있으면: `[STEP 0] ❌ 미커밋 변경 — /push 먼저` 후 중단.

## STEP 1 — E2E Smoke PreFlight (배포 차단 게이트)

이번 배포 변경이 아래 trigger 영역에 영향을 주면, 대표 경로 통합 테스트를 신설/갱신했는지 점검.

**Trigger 영역**:
1. 파싱·색인(`src/parser/`, `src/ingest/`) — XML→노드·본문·색인·토큰화
2. 검색(`src/search/`, `src/db/`) — 한자 BM25·군집·구조조회·이표기·FTS5 마이그
3. 공개 API·CLI(`src/index.ts`, `src/history-db.ts`, `src/bundled-db.ts`, `src/cli/`)

**e2e 3표면 점검**(AGENTS.md 철학 — 배포 산출물이 실제 동작하는가):
- **라이브러리** — `openBundledDb()`로 동봉 코퍼스 열어 신규 공개 메서드가 기지 결과 반환(`tests/*.e2e`·`search-*.test.ts` 등)
- **MCP** — 서버 띄워 신규/변경 도구 실제 호출, 스키마·반환 계약(`tests/mcp/server.e2e.test.ts`)
- **CLI** — `krh`를 서브프로세스로 실행해 stdout 검증(`tests/cli/krh.e2e.test.ts`)

```bash
git diff --name-only main..dev -- src/ | head -30
grep -rl "openBundledDb\|callTool\|execFileSync" tests/ | sort   # e2e 표면 커버 확인
```
- 신규 공개 기능(API/CLI/MCP)인데 위 3표면 중 해당 e2e가 **없으면 작성**한다. 있으면 갱신 여부 확인.
- 변경 있음 + 대표 경로·e2e 신설/갱신 → `[STEP 1] ✅ trigger 변경 + e2e 확인`
- 변경 있음 + 미갱신 → 🔴 `[STEP 1] 🔴 trigger 변경 but e2e 미작성 — 작성 필요 (계속? y/N)` PM `y` 아니면 중단.

## STEP 1.5 — 문서(README) 현행화 (배포 전 필수)

공개 표면(API·CLI·MCP)이 바뀌었으면 README를 **코드 실측과 일치**시킨다. npm 패키지 페이지가 곧
README이므로 드리프트는 배포 전 반드시 해소한다.

**점검 항목** — 각 표/절이 실제 코드와 일치하는가:
- API 레퍼런스 표 = `src/history-db.ts` 공개 메서드
- CLI 레퍼런스 표 = `src/cli/krh.ts` 커맨드·옵션(`--index` 값 등)
- MCP 도구 목록·개수 = `src/mcp/tools.ts` 등록 도구(`registerTool`)
- 코퍼스 구성·현황 + 버전 = 실제 코퍼스·`package.json` version
- 로드맵 = 완료분 반영(예정→✅)
- English Overview = 신기능 반영(발견성)

```bash
grep -c "registerTool" src/mcp/tools.ts        # MCP 도구 개수
grep "\.command(" src/cli/krh.ts               # CLI 커맨드
grep -E "^\s+\w+\(" src/history-db.ts | head   # 공개 메서드 스캔
```
- 드리프트 있으면 README 갱신 → 커밋(`docs: README 현행화`) → `/push`. 없으면 `[STEP 1.5] ✅ 문서 현행화 확인`.

## STEP 3 — 버전 bump(dev) → dev → main PR

> 🔒 `main` 직접 push 금지 — 버전 bump 커밋은 반드시 PR 에 실어 보낸다.

```bash
npm version <patch|minor|major> --no-git-tag-version   # package.json + lock 만 갱신(커밋·태그 X)
git commit -am "chore(release): v<X.Y.Z>"
git push origin dev
gh pr create --base main --head dev \
  --title "release: v<X.Y.Z> — <요약>" \
  --body "변경 요약 / 검증 결과(테스트 N개) / 대표 경로"
```
- PR URL 출력 → PM 검토·머지 대기(또는 PM 명시 시 `gh pr merge --squash`).

## STEP 4 — 태그 push → OIDC 자동 publish (main 머지 후)

`v*` 태그 push 가 곧 배포 트리거 — `.github/workflows/publish.yml`(OIDC)이 토큰 없이 `npm publish --provenance` 수행.

```bash
git checkout main && git pull origin main
git tag v<X.Y.Z> && git push origin v<X.Y.Z>          # → publish.yml trigger (main 직접 push X)
gh run list --workflow=publish.yml --limit=1
gh run watch <id>
npm view kr-history-bm25 version                       # 게시 확인
```
- 🔴 `git push origin main` 직접 push 금지(protection 차단) — 버전 bump 는 STEP 3 PR 로 반영됨.
- (Actions 실패·긴급 시 fallback) 로컬: `npm run build && npm publish --provenance --access public`(Automation 토큰 필요).

## STEP 5 — 마무리

```bash
git checkout dev && git merge main   # main 의 version bump 를 dev 에 backsync
git push origin dev
```
