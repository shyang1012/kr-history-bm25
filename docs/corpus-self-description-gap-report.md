## 0. 한 줄 판정

**이 서버는 「무엇을 담고 있는가」를 말할 수단이 없다.** `corpus` 테이블에 `name`은 있고
**설명이 없으며**, 도구 8종이 전부 내용 검색이라 **코퍼스 자체를 묻는 질의에 답할 도구가 없다.**
그 결과 소비자(LLM)는 코퍼스의 성격을 **추측**하고, 실측에서 **정반대로 틀렸다.**

🔴 고칠 자리는 소비자 쪽 프롬프트가 아니다. **서버가 선언하지 않는 것을 소비자가 알 방법이 없다.**

## 1. 실측 — 같은 세션에서 모델이 스스로 반증했다

pearjun + `krh-mcp` + DNA3.0-27B(온프렘 vLLM), 2026-08-20.

**질의 A** — "낙랑은 단순한 한나라 군현이었는지 사서 원문을 찾아 분석해줘" (도구 9회, `recovered`)

모델이 근거로 이렇게 인용했다:

> 「景初中,明帝密遣帶方太守劉昕·樂浪太守鮮于嗣越海定二郡」**[57630]**

**질의 B**(직후) — "코퍼스에 삼국지가 있어?" (도구 1회, `raw`)

같은 모델이 이렇게 답했다:

> "**삼국지 원문 자체**가 코퍼스에 직접 포함되었는지 **명확하지 않습니다** … 확인된 것은
> 삼국지 내용을 **인용하거나 분석**한 **현대 연구 자료**들"

🔴 **직전 질의에서 자기가 인용한 [57630]이 『三國志』魏書 東夷傳 韓條 원문이다.**

### 1-1. 검증

```
search_han('景初中明帝密遣帶方太守劉昕', corpusCode='ko')

[57630]  nodeId ko_022_0350_0010  corpusCode ko
         「景初中,明帝密遣帶方太守劉昕·樂浪太守鮮于嗣越海定二郡,諸韓國臣智加賜邑君印綬…」
[68116]  nodeId ko_041_0230_0060  corpusCode ko
         「魏景初中(237~239),明帝密遣帶方太守劉昕·樂浪太守鮮于嗣越海定二郡…」
```

**`ko`(고대사료집성)에 三國志 東夷傳 원문이 그대로 있다.** 같은 대목이 두 계열로 수록돼 있기까지 하다.

**PM 확인**: *"고대사료집대성은 **대륙의 25사 중 동이와 연관된 내용을 모아둔 것**"* —
즉 `ko`는 **1차 사료 발췌 모음**이다. 모델은 이것을 「현대 연구 자료」라고 **정반대로** 서술했다.

### 1-2. 🔴 두 번째 증상 — 코퍼스 메타 질의는 통째로 실패한다

**질의 C** — "고대사료집대성의 내용은?" → **`failed`**(도구 6회 · 모델 4회 · 25.3s)

두 가지가 겹쳤다:

1. 이름이 **한 글자** 다르다(집**대**성 vs 집성) — 내용 검색으로는 잡히지 않는다
2. 🔴 **더 근본적으로, 답할 도구가 없다.** `search_han`·`search_ko`·`search_hybrid`·
   `search_by_reading`·`with_variants`·`cluster`·`place_clusters`·`lookup_place` —
   **8종 전부 내용 검색·군집·조회**다. 「어떤 코퍼스가 있나」·「무엇이 들어 있나」를
   **묻는 도구가 없다.**

사용자에게는 「25초를 쓰고 모른다고 답하는 시스템」으로 보인다.

## 2. 🔴 왜 이것이 소비자 결함이 아닌가

소비자(pearjun)는 이미 **줄 수 있는 것을 다 주고 있다.** 최근 작업(pj-1xs9)에서 도구 결과 렌더를
이렇게 바꿨다:

```
[67362] (고대사료집성 ko_038_0480_0010) 遼東張統據樂浪·帶方二郡…
```

그 전에는 서버가 준 `corpusCode`·`nodeId`를 어댑터가 **버리고 있었고**, 그래서 모델이 서명을
지어냈다. 지금은 **이름이 보인다.**

🔴 **그런데 이름만으로는 성격을 알 수 없다.** 모델은 「고대사료집성」이라는 낯선 서명과 중국사
내용을 보고 **추측**했고, 틀렸다. **이름 다음 층의 정보를 아무도 갖고 있지 않다.**

### 2-1. 서버에도 그 정보가 없다

`src/db/schema.ts`:

```ts
export const corpus = sqliteTable('corpus', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  code: text('code').notNull().unique(),
  name: text('name').notNull(),          // ← 「고대사료집성」
  sourceDir: text('source_dir').notNull(),
  dtdVersion: text('dtd_version'),
  ingestedAt: text('ingested_at'),
});
```

🔴 **`description`이 없다.** 이 코퍼스가 「25사 동이 관련 발췌」라는 사실이 **DB 어디에도 없다.**
즉 소비자가 물어봐도 서버가 답할 근거가 없다.

### 2-2. 유일한 설명이 손으로 유지되는 문자열이다

`src/mcp/tools.ts`:

```ts
const corpusCodeSchema = z
  .string()
  .optional()
  .describe('코퍼스 코드로 제한(sg=삼국사기·sy=삼국유사·kr=고려사·kj=고려사절요·ko=고대사료집성)');
```

이것이 현재 **유일한 코퍼스 목록**이고, 소비자(pearjun 어댑터)는 **이 문자열을 전사해서** 자기
상수를 만들었다. 즉 **도구 파라미터 설명이 사실상의 스키마 역할**을 하고 있다.

### 2-3. 🔴 그리고 이미 드리프트했다

같은 저장소 안에서 **세 곳이 다르게 적혀 있다**:

| 위치 | 코드 목록 |
|---|---|
| `src/db/schema.ts` 주석 | `sg/ss/kr/kj/**ka**` |
| `src/mcp/tools.ts` describe | `sg/**sy**/kr/kj/**ko**` |
| 실제 데이터(관측) | **`ko`** 확인됨 (위 검증) |

`ss`·`ka`는 실재하지 않을 가능성이 높다(미검증 — 이 보고서는 `ko`만 직접 확인했다).
🔴 **어느 쪽이 참인지 코드만 봐서는 알 수 없다는 것 자체가 결함**이다. 손으로 유지되는 두 곳이
이미 갈렸고, 소비자는 그중 하나를 베꼈다.

## 3. 🔴 이 결함의 성질 — 접지 검사로는 절대 안 잡힌다

질의 B의 답변은 **인용이 실재한다**(`[57833]`·`[57834]`). 그래서 소비자 런타임에서
`ungroundedIds: 0` · `grounded: true` · `successClass: raw`로 **통과했다.**

**근거는 진짜인데 근거에 대한 서술이 날조다.**

- 인용 실재 검사 → 통과 (id가 실제로 있다)
- 인용 비중·중복성(IG)·기여율 → 통과 (문장들이 서로 다른 정보를 담고 주제어도 겹친다)
- 🔴 **틀린 것은 「사실 내용」이고, 자동 판정축은 전부 구조적 대리다**

즉 **소비자 쪽에 어떤 게이트를 더 붙여도 이 유형은 못 잡는다.** 정보를 주는 것 말고는 길이 없다.

## 4. 제안

### 4-1. `corpus`에 설명 컬럼을 둔다 (필수)

```ts
export const corpus = sqliteTable('corpus', {
  // …
  name: text('name').notNull(),
  /** 🔴 이 코퍼스가 무엇인가 — 소비자(LLM)가 성격을 추측하지 않게 한다. */
  description: text('description'),
});
```

예: `ko` → *"중국 정사 25사 가운데 동이(東夷) 관련 기록을 발췌·집성한 자료. 『三國志』魏書
東夷傳, 『後漢書』東夷列傳 등의 **원문**을 포함한다."*

🔴 **`name`을 늘려 해결하지 않는다** — 이름과 설명은 다른 축이고, 이름을 문장으로 만들면
인용 표기(`(고대사료집성 ko_022_0350_0010)`)가 망가진다.

### 4-2. 코퍼스 메타 도구를 추가한다 (필수)

```
list_corpora  →  [{ code, name, description, passageCount?, ingestedAt? }, …]
```

🔴 **이 도구는 「근거를 내는 도구」가 아니다.** 소비자 쪽 계약(pearjun `extractEvidence`)에서
**목록·탐색 도구는 `undefined`를 반환해야** 하며, 빈 배열(`[]`)을 반환하면 **근거 0건으로
오판되어 파이프라인이 멈춘다**(그쪽 실측 이력이 있다). 도구 설명에 **「검색 결과가 아니다」**를
명시하면 소비자가 분류하기 쉽다.

또한 이 도구가 있으면 §1-2의 「한 글자 다른 이름」 문제가 **자연히 해소된다** — 모델이 목록을
받아 「집대성이 아니라 집성이군」을 스스로 맞출 수 있다.

### 4-3. `corpusCodeSchema.describe()`를 DB에서 생성한다 (권장)

손으로 유지되는 문자열이 **사실상의 스키마**가 되어 있고 이미 드리프트했다(§2-3).
서버 기동 시 `corpus` 테이블을 읽어 description 문자열을 **조립**하면:

- 코퍼스를 늘려도 도구 설명이 자동으로 따라온다
- 소비자가 전사한 상수가 낡는 문제도 **출처가 하나**가 되어 줄어든다

### 4-4. `ingestedAt`을 노출한다 (권장)

이미 컬럼이 있는데 **밖으로 안 나간다.** RAG를 쓰는 소비자에게는 「이 코퍼스가 언제까지를
아는가」가 답변 신뢰도의 일부다. 사서는 시점이 고정돼 있어 덜 민감하지만,
**계약을 만들어 두는 비용이 지금이 가장 싸다.**

---

## 5. 🔴 하지 않을 것

- **소비자 프롬프트로 고치기** — *"코퍼스 성격을 추측하지 마라"*는 지시로는 안 된다.
  모델이 **모르는 사실**을 지시로 채울 수 없다. 정보를 주는 것이 답이다.
- **소비자 쪽 상수에 설명을 하드코딩하기** — 지금 이름이 그렇게 되어 있고(§2-2),
  그것이 드리프트의 원인이다. **같은 실수를 한 층 더 쌓는 것**이다.
- **`name`에 설명을 욱여넣기** — §4-1.

## 6. 우선순위

| # | 항목 | 성격 | 근거 |
|---|---|---|---|
| 1 | `corpus.description` + `list_corpora` | **필수** | 실측 오답 2건의 직접 원인 |
| 2 | `describe()` 자동 생성 | 권장 | 이미 드리프트 실재(§2-3) |
| 3 | `ingestedAt` 노출 | 권장 | 계약을 지금 만드는 것이 싸다 |

🔴 **1은 서로를 필요로 한다** — 설명 컬럼만 있고 도구가 없으면 밖에서 못 읽고, 도구만 있고
설명이 없으면 이름만 또 돌려준다.

## 7. 조치 기록 (2026-08-21 · `krh-i2o`)

### 7-1. 실측으로 확인한 것

보고 내용은 전부 사실이었고, **드리프트는 보고서가 적은 것보다 한 겹 더** 있었다.

| `schema.ts:23` 주석 | `sg/ss/kr/kj/ka` | **`ss`·`ka`는 실재하지 않음** |
| `tools.ts` describe | `ko=고대사료집성` | **`ko=한국고대사료집성`**(이름까지 틀림) |
| `search_ko` 설명 | "번역 완료 코퍼스(삼국사기·삼국유사)" | **고려사 10,256건(28%) 누락** |

### 7-2. 한 것

| # | 항목 | 조치 |
|---|---|---|
| 1 | `corpus.description` | `src/db/migrations/0005-corpus-description.ts` — 컬럼 추가 + backfill. 🔴 SQL을 **레지스트리에서 생성**한다 |
| 1 | `list_corpora` | MCP 도구 9번째. `note`에 **「검색 결과가 아니다」** 명시(소비자 `extractEvidence` 오분류 방지) |

### 7-3. 🔴 gz 재생성이 필요 없다

`openBundledDb()` → `HistoryDb.open()` → `runMigrations()` 경로라, **기존 0.4.0/0.5.0 추출본도 다음 오픈 때
0005를 받아** 설명이 채워진다. e2e(`tests/mcp/server.e2e.test.ts`)가 실제 동봉본으로 이 업그레이드 경로를
검증한다.

### 7-4. 남긴 판단

- **미등재 코퍼스는 `description = null`** — 사용자가 자체 ingest한 코퍼스에 설명을 **지어내지 않는다**.
- `status`(정사/야사)·`form`(기전체/편년체)·`perspective`(내부/외부) **축 분리는 하지 않았다**.
  이번엔 설명 문장에 담았고, 구조화는 메타규칙 코퍼스(`krh-bqp`)의 몫이다.

### 7-5. 검증

`npm run validate` 통과 — 260 tests / 29 files. MCP e2e에서 도구 9종 노출 + 동봉본 `list_corpora` 실호출로
`ko` 설명(「발췌」) 확인, CLI e2e에서 `krh corpora` stdout 확인.
